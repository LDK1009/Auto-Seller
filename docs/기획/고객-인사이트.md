# 고객 인사이트 — 실제로 들은 것만

> 추측·가설이 아니라 **실제 고객에게서 나온 것**만 기록한다. 출처와 표본 크기를 반드시 함께 적는다.
> 기획·마케팅 판단의 1차 근거. [PLAN.md](./PLAN.md)의 타겟·페인포인트 정의를 이 파일이 검증·수정한다.

---

## 확인된 것

### ① 이미지 편집이 가장 오래 걸린다 ⭐ 핵심 검증

| 항목 | 내용 |
|---|---|
| 출처 | 쓰레드 설문 "위탁판매 준비에서 제일 오래 걸리는 작업" |
| 표본 | 7표 |
| 결과 | **이미지편집 5표 (71%)** / 상품명·태그짓기 / 가격계산 |
| 일자 | 2026-07 |

**행동 데이터가 교차 검증한다** — GA4(7/21-23, 봇 제외)에서 `zip_download` 2건, `domeggook_lookup` 7건. 말한 것과 실제 행동이 일치.

> 표본 7은 작다. 다만 우리 제품의 핵심 가설(이미지 가공이 병목)을 지지하는 첫 외부 근거.

### ② 재고관리(품절 대응)가 어렵다

| 항목 | 내용 |
|---|---|
| 출처 | 쓰레드 소통 중 셀러 의견 |
| 표본 | 2건 |
| 내용 | 판매가 들어왔는데 도매처는 품절 — 이 상황 대응이 힘들다 |

**현재 범위 밖.** [PLAN.md](./PLAN.md) 8장 S5(주문→자동 발주) 소관. 우리 타겟(첫 등록 전 초보)의 문제가 아니라 판매 발생 후의 문제이며, 실시간 재고 동기화는 1인 운영 상한을 넘는다.
→ **S5 진입 판단 시 근거로 사용.** 의견이 더 쌓이면 우선순위 재검토.

### ③ 셀러의 성장 경로

| 항목 | 내용 |
|---|---|
| 출처 | 쓰레드에서 특정 셀러에게 활동 과정 질의 |
| 표본 | 1건 (정성) |
| 내용 | **초기: 키워드 중심으로 상품을 찾아 다량 업로드** → 판매 발생 → **주력 상품 등장** → 그 상품의 키워드·카테고리로 스토어를 집중 구성 |

**제품 함의:**
- 초기 구간(키워드 탐색 → 다량 등록)이 우리 도구가 붙는 자리 — 키워드 분석·원링크가 정확히 이 단계
- 주력 상품 이후 구간은 우리 범위 밖 (스토어 운영·광고)
- 단, 등록 한도제(26.6)로 **"다량 업로드" 전략 자체가 막혔다** — 이 경로가 바뀌는 중일 수 있음. 추가 확인 필요

## 확인이 필요한 것 (다음 설문 후보)

- 상품 하나 등록에 실제 몇 분 걸리나
- 이미지 작업 중 제일 귀찮은 단계 (누끼 / 규격 / 워터마크 / 상세분할)
- 지금 가장 막혀 있는 단계 (소재선정 / 소싱 / 가격 / 등록 / 노출)
- 한도제 이후 등록 전략이 바뀌었나

---

## 기록 원칙

1. **출처·표본 크기 필수** — 없으면 적지 않는다
2. **말(설문·인터뷰)과 행동(GA4)을 구분**하고, 일치하면 명시
3. 표본 1-2건은 "정성 참고"로 표기, 단정하지 않는다
4. 범위 밖 의견도 기록 — 나중 단계의 근거가 된다
