# Auto-Seller 기능 로드맵

> 최종 수정: 2026-07-06
> 포지셔닝: **셀러 워크플로 ② "상품 등록 준비~등록" 전담** — "팔 것을 정한 셀러가 스토어에 상품을 올리기까지"
> 확장 원칙: ② 안에서 셀러가 다른 툴을 열 필요가 없어질 때까지 딥다이브. 그 전에 다른 단계(조사·마케팅·주문·정산) 진출 금지.
> 차별화 축: 개별 기능이 아니라 **"소싱→이미지→상품명→상세→등록" 통합 파이프라인** (개별 기능은 전부 경쟁자 존재, 파이프라인은 전무)

## Phase 1 — 이미지 스테이션 (무료·무가입·브라우저 처리)

목표: 이미지 작업에서 포토샵·드랩아트·remove.bg를 열 필요 없게.

- [x] 1. 배경 제거(누끼) — 대량 처리, 배경 교체(색·패턴·그라데이션·검색 이미지), ZIP
- [x] 2. **이미지 규격 일괄 변환**
  - 마켓별 프리셋(스마트스토어 1000×1000, 쿠팡 정방형 등), 리사이즈·정방형 캔버스·용량 압축
  - ★ 누끼 결과를 바로 이어받는 파이프라인 연결 (차별화 시작점) — 완료
- [x] 3. 이미지 규정 검사기 — 업로드 시 규격·용량 자동 판정 → "여기서 바로 변환" 연결 (유입구 겸용)
- [x] 4. 워터마크 일괄 삽입 — 로고/텍스트, 위치·투명도
- [x] 5. 상세페이지 이미지 분할 — 마켓 높이 제한 대응

## ★ 도매매 피벗 — 최소유효시장 맞춤 (2026-07-06 확정)

타깃 확정("국내 초보 1인 위탁 셀러", [SERVICE.md](./SERVICE.md) 2장)에 따라 제품을 도매매 소싱 흐름에 최적화한다.
원칙: 내 이미지 가공은 브라우저 / 공개 상품 데이터·외부 API는 서버 프록시(`app/api`) 경유 (CORS·키 은닉).

- [x] P-0. **(선행) 도매매/도매꾹 오픈API 스펙·약관 확인** — 2026-07-06 완료, **P-1 청신호**
  - 상품상세정보 API(`mode=getItemView`)는 **Open API 키로 즉시 사용 가능** (키 발급 완료 상태). 도매꾹·도매매 통합 조회(v4.1+)
  - 이미지: `thumb.original`(판매자 원본)·PNG 변환본 + `desc.contents.item`(상세 HTML→img 추출). multiple 최대 100개 → P-2도 동일 API로 커버
  - Private(승인 2~3일)는 주문·상품등록 계열만 — P-1 불필요
  - 미확인(비차단): rate limit 미명시(프록시 캐싱으로 보수 운용), 이미지 사용 약관 원문(확인 예정, 문의처 techsupport@ggook.com)
  - **분기 확정: P-1 포함 출시, 타임박스 2~3주**
- [ ] P-1. **도매매 URL/상품번호 파싱** — 붙여넣으면 대표·상세 이미지를 프록시로 가져와 파이프라인(누끼→규격→분할)에 바로 투입 (수동 다운로드/업로드 생략)
- [ ] P-2. **도매매 대량등록 엑셀 이미지 매칭** — 엑셀 업로드 → 이미지 URL 추출 → 일괄 가공 → ZIP. ⚠️ 기술 검토 선행: 대량 처리 시간(브라우저 CPU 기대치 관리), 통이미지 canvas 크기 한계(크롬 한 변 ~32,767px)
- [ ] P-3. **역산 마진 계산기** — 도매매 공급가 입력 → 목표 마진율 확보에 필요한 최소 판매가 역산 (마켓 카테고리별 수수료 프리셋). 기존 마진 계산기 고도화, API 불필요 → 즉시 착수 가능
- [ ] P-4. 규격 변환에 **지정 구역 크롭 프리셋** — 공급사 대표이미지의 상·하단 문구 영역 잘라내기
- [ ] P-5. 상세 분할 고도화 — **JPG 압축 기본** (WebP는 마켓 업로드 지원 확인 후 옵션)
- 보류: 스마트 지우개(inpainting) — 범용 '지우개' 네이밍으로 법적 노출은 완화 가능하나(용도 마케팅 금지, SERVICE.md 9장), 브라우저 모델 용량·품질 문제로 기술 검토 후 재논의
- ❌ 제외 확정: 공급사 평점·품절 리스크 배지 (SERVICE.md 9장 비목표)
