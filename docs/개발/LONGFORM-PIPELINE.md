# 롱폼 파이프라인 설계안 (초안 — 2026-07-21)

유튜브 롱폼을 주축으로 전환하면서 필요한 제작 파이프라인. 기존 `tools/shorts-studio/`를 재조준한다(재작성 아님).

## 1. 설계 축 — 오디오가 타임라인을 지배한다

숏츠와 롱폼의 근본 차이다.

| | 숏츠 (현행) | 롱폼 (신규) |
|---|---|---|
| 타임라인 기준 | **화면 녹화** — 녹화 길이가 영상 길이 | **TTS 오디오** — 나레이션 길이가 영상 길이 |
| 자막 배치 | 정차역에 스냅 (추정) | 문장별 오디오 길이로 **정확히 결정** |
| 화면 | 1개 시나리오 통째 | 챕터별 여러 시나리오 |
| 비율 | 세로 9:16 | 가로 16:9 |
| BGM | 필수 (무음 방지) | 불필요 — 나레이션이 채움 |

**핵심**: TTS를 **문장 단위로 개별 호출**해 각 mp3의 실제 길이를 측정한다. 그러면 싱크 추정이 사라진다. 숏츠에서 자막-정차역 스냅이 어긋나던 문제가 구조적으로 해결된다.

## 2. 데이터 흐름

```
대본.md  (챕터 · 문장 · 화면 지시)
   │
   ├─ parse ─────────→ 문장 배열
   │                   [{ chapterId, text, screen: {scenario, station} }]
   │
   ├─ TTS (문장별) ──→ audio/{n}.mp3 + durationSec 측정
   │
   ├─ 화면 녹화 ─────→ rec/{scenario}.webm + 이벤트 로그
   │                   (기존 recorder.ts 재사용, 뷰포트만 가로로)
   │
   ├─ 타임라인 조립 ─→ props.json
   │                   [{ from, to, text, audioSrc, videoSrc, videoOffset }]
   │
   ├─ Remotion 렌더 ─→ 롱폼.mp4 (1920×1080)
   │
   └─ 구간 추출 ─────→ 숏폼 3~4개 (9:16 크롭 + 자막 확대)
```

## 3. 대본 포맷 (제안)

`docs/마케팅/컨텐츠/{월}/{일}/롱폼/대본.md`

```markdown
---
제목: 도매꾹 위탁판매 시작하는 법 — 상품 찾기부터 등록까지
검색어: 도매꾹 위탁판매
페르소나: 직장인 부업
숏폼추출: [2, 4]        # 숏폼으로 뽑을 챕터 번호
---

## 1. 도매꾹이 뭔가
[화면: 인트로]

위탁판매를 알아보면 도매꾹이라는 이름이 계속 나옵니다.
막상 들어가보면 뭘 어떻게 해야 할지 막막하죠.
오늘은 상품 하나를 실제로 찾아서 등록까지 해보겠습니다.

## 2. 상품 찾기
[화면: domeggook-search, 키워드=주방수납]

먼저 팔 상품을 찾아야 합니다.
(정차역) 검색창에 카테고리를 넣습니다.
(정차역) 인기순으로 정렬하면 실제로 팔리는 상품이 위로 옵니다.
```

**규칙**
- 문장 1줄 = TTS 1호출 = 자막 1줄. 줄바꿈이 곧 호흡
- `(정차역)` 표시가 있는 문장은 해당 화면 강조 시점과 정렬
- `[화면: ...]`이 챕터의 녹화 시나리오를 지정. `인트로`는 녹화 없이 카드만

## 3-1. AI 티 제거 — 구현 요구사항

규칙의 단일 출처는 [MARKETING.md](../마케팅/MARKETING.md) "화면에서도 AI 티가 난다". 여기는 코드로 어떻게 지킬지.

| 규칙 | 구현 |
|---|---|
| **롱폼 자막 최소화** | 대본에서 `**강조**` 표시된 문장만 자막 렌더. 나머지는 음성만. 숏폼 컴포지션은 전문장 자막 |
| **불균일 간격** | 문장 간격을 성격별로: 챕터 마지막 문장 뒤 `1.0s` · 정차역 문장 뒤 `0.8s` · 일반 `0.35s` |
| **화면 전환 무음** | 챕터 시작 시 첫 문장을 `0.8s` 늦춰 배치 — 화면이 먼저 보이고 말이 뒤따른다 |
| **인트로 카드 없음** | `screen: 인트로`는 카드가 아니라 **직전 화면 유지 또는 관련 이미지**. 타이틀 모션 금지 |
| **easing 필수** | 모든 `interpolate`에 `easing: Easing.bezier(0.4, 0, 0.2, 1)`. 등속 금지 |
| **커서 자연화** | `humanize.ts` — 베지어 경로 + 목표 근처 감속 + 3-5px 오버슈트 후 복귀 |
| **편별 변주** | 자막 y위치를 `hash(제목) % 3` 으로 3단계 중 선택 — 결정적이라 재렌더해도 동일 |

> ⚠️ Remotion 스크립트에서 `Math.random()` 사용 금지 (재현성 파괴 — 재렌더 시 결과가 달라진다). 변주가 필요하면 **제목·인덱스 해시 기반 결정적 변주**를 쓴다.

## 4. 타임라인 계산

```
문장 i의 시작 = Σ(문장 0..i-1 의 오디오 길이) + 문장간 간격
문장 i의 자막 = 그 구간 그대로
챕터 c의 화면 = 챕터 첫 문장 시작 ~ 마지막 문장 끝
```

**화면 길이 조정**: 녹화가 나레이션보다 짧으면 마지막 프레임 정지, 길면 배속. 숏츠의 로딩 배속 로직을 재사용한다.

## 5. 파일 구성 (신규·수정)

| 경로 | 상태 | 내용 |
|---|---|---|
| `scripts/lib/tts.ts` | 신규 | ElevenLabs API 호출, 문장별 mp3 생성·길이 측정·캐시 |
| `scripts/parse-longform.ts` | 신규 | 대본 md → 챕터·문장·화면 지시 파싱 |
| `scripts/build-longform.ts` | 신규 | 원커맨드 (TTS → 녹화 → 조립 → 렌더) |
| `scripts/extract-shorts.ts` | 신규 | 롱폼에서 숏폼 구간 추출 |
| `remotion/LongForm.tsx` | 신규 | 가로 16:9 합성 (챕터 타이틀·자막·화면·강조 링) |
| `scripts/lib/recorder.ts` | 수정 | 뷰포트를 가로/세로 선택 가능하게 (`VIEWPORT_DESKTOP` 추가) |
| `remotion/components/*` | 재사용 | HighlightRing·SafeArea 등 비율만 조정 |

## 5-1. 분량·렌더 비용 (2026-07-21 실측)

분량 규칙의 단일 출처는 [MARKETING.md](../마케팅/MARKETING.md). 여기는 제작 비용 환산.

| 산출물 | 길이 | 프레임(30fps) | 렌더 소요 |
|---|---|---|---|
| 롱폼 | 10분 | 18,000 | 약 36분 |
| 숏폼 | 60초 × 4 | 1,800 × 4 | 약 15분 |
| **소재 1개 총** | | | **약 50분** |

**실측 근거:** 기존 숏츠(33초·990프레임) 렌더에 **2분 0초** = 8.25fps = 실시간의 3.6배. `remotion render TimerShort` 기준.

> **부분 렌더 필수.** 36분짜리를 실수 하나로 통째 재렌더하면 손실이 크다(숏츠 36편 중 6편이 시나리오 오류로 재작업했던 전례). `--frames=시작-끝`으로 챕터 단위 재렌더를 처음부터 지원한다:
> ```bash
> npm run longform -- {소재} --chapter=3   # 3챕터만 재렌더 후 교체
> ```

## 6. TTS 연동

- 제공자: ElevenLabs (Creator $22/월, 월 100,000 크레딧)
- 키: `.env.local`의 `ELEVENLABS_API_KEY` · `ELEVENLABS_VOICE_ID` (서버 전용, `NEXT_PUBLIC_` 금지)
- **모델: `eleven_multilingual_v2`** · 보이스: Professional Voice Clone(한국어 네이티브) — PVC는 **Creator 이상** 필수 (Free·Starter는 402)
- **오디오 길이 측정: `npx remotion ffprobe`** — Remotion 번들 ffmpeg 사용, 새 의존성 0 (검증 완료)
- **해시 캐시 동작 확인** — 동일 문장 재실행 시 API 미호출 (신규 0 / 캐시 3)

**실측 (2026-07-22, 3문장):**

| 항목 | 값 |
|---|---|
| 발화 속도 | **초당 6.1-6.5자 = 분당 385자** (공백 제외) |
| 문장 간 간격 포함 실효 | **분당 약 340자** |
| 크레딧 | 1자 = 1크레딧. 편당 약 2,300 (Creator 10만 = 월 43편) |

> 문서 기준이던 "분당 300자"는 실측보다 28% 느렸다. MARKETING.md 분량표를 실측값으로 갱신함.
- **캐시 필수**: 대본 문장 해시로 캐싱. 문장 하나 고쳤다고 전체 재생성하면 크레딧이 낭비된다
- API 키는 `.env.local`에 `ELEVENLABS_API_KEY` (서버 전용, `NEXT_PUBLIC_` 금지)

## 7. 작업 순서

| 단계 | 내용 | 검증 |
|---|---|---|
| 1 | `tts.ts` — 문장 배열 → mp3 + 길이 | 문장 3개로 길이 측정 정확한지 |
| 2 | `parse-longform.ts` — 대본 파싱 | 챕터·문장·화면 지시가 구조로 나오는지 |
| 3 | `recorder.ts` 가로 지원 | 데스크톱 뷰 녹화가 잘리지 않는지 |
| 4 | `LongForm.tsx` — 합성 | 자막이 오디오와 정확히 맞는지 |
| 5 | `build-longform.ts` — 원커맨드 | 파일럿 1편 완주 |
| 6 | `extract-shorts.ts` — 숏폼 추출 | 9:16 크롭에서 화면이 안 잘리는지 |

**파일럿 1편으로 1~5단계를 검증한 뒤 실제 소요 시간을 측정한다.** 그 실측으로 주간 편수를 정한다(현재 미정 — 추측으로 정하지 않는다).
