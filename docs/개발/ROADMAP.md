> **판정 기준:** 이 기능이 "지금 도매꾹에서 떼다 스마트스토어에 올리는 사람"의 반복 작업을 줄이는가? 아니면 우선순위 밖이다.

- **개발 순서: ②a 등록 준비 완성 → 그 후 ②b 등록 실행.**
- **출시 구성: 셀러의 반복 사이클 순서(소싱 → 계산 → 등록 준비)로 구성한다.** 중심은 ②a(등록 준비)지만 그것만으로 출시하지 않는다 — 소싱·계산 진입로가 함께 있어야 사이클이 이어진다.
- **기능 우선순위는 고객 인사이트가 정한다** — [고객-인사이트.md](../기획/고객-인사이트.md)에 검증된 pain 순서. 현재 1위: **이미지 가공**(설문 71%)
- **범위 밖:** 셀러가 되기 전 단계(사업자등록·스토어 개설 안내), 판매 후 운영(재고·CS·광고) — 후자는 S5 이후

### 판정 구간 재설계 스펙 (2026-07-24 확정 — 실측 30개 기준)

**실측 분포** (도매꾹 위탁 대상 키워드 32개 조회, 2개는 데이터 없음)

| 지표 | 값 | 지표 | 값 |
|---|---|---|---|
| 최소 | 2.03 (무선고데기) | 중앙 | 81.35 |
| p10 | 7.06 | p75 | 524.53 |
| p25 | 38.06 | 최대 | 15,878 (LED목걸이선풍기) |

**뒤집힌 전제 2가지**

1. `ratio < 1` = 틈새는 **실재하지 않는 구간**이다. 최소가 2.03이라 아무도 초록을 못 받는다.
2. **롱테일일수록 ratio가 나쁘다.** 접이식캠핑화로대 3907(검색 39회) · 실리콘주방주걱세트 2435(검색 18회) — 검색량이 바닥이라 나눗셈이 폭발한 것이지 경쟁이 심한 게 아니다. **"수요 없음"과 "경쟁 치열"은 완전히 다른 문제인데 같은 빨간 배지로 뭉개진다.**

**새 판정 로직** — 검색량 게이트를 먼저 통과시킨 뒤 ratio를 본다

```
0) 월간 검색수 < 100        → "수요 없음"  (회색)  ← ratio 계산 자체를 하지 않는다
1) ratio < 10               → "기회"      (초록)  p10=7 근처, 상위 10%
2) ratio < 50               → "해볼만"    (연초록) p25=38
3) ratio < 200              → "빡셈"      (주황)  중앙 81
4) ratio >= 200             → "치열"      (빨강)  p75=524
※ 월간 검색수 100-500이면 판정과 별개로 "수요 적음" 보조 표시
```

**적용 후 실측 분포** — 기회 5 · 해볼만 6 · 빡셈 8 · 치열 8 · 수요없음 3 (n=30)
기존에는 30개 전부 "치열"이었다.

**대상**: [judgeCompetition.ts](../../src/views/keyword-stats/_utils/judgeCompetition.ts) — 스탯 카드·연관 표·비교 표가 공유하는 단일 기준이라 한 곳만 고치면 전 화면에 반영된다. 검색량 게이트는 `monthlySearches`를 인자로 추가로 받아야 한다.

### 심은 이벤트 (2026-07-27 구현 완료)

> 구현 결과가 초안 스펙과 한 군데 다르다: `lookup_fail_reason`을 **별도 이벤트로 만들지 않고 기존 `domeggook_lookup`에 파라미터로 합쳤다.** 조회 1회 = 이벤트 1개가 GA4 탐색에서 훨씬 다루기 쉽다.

| 이벤트 | 파라미터 | 발생 지점 | 목적 |
|---|---|---|---|
| `domeggook_lookup` | `result`, **`reason`**, **`license`** | `DomeggookImportView.tsx` | 진입 실패 원인 분해 |
| **`sheet_view`** | `license` | `RegistrationSheet.tsx` (상품별 1회) | **시트 도달 = 퍼널의 진짜 분모** |
| **`section_copy`** | `section`, `label` | `RegistrationSheet.tsx` `copyText()` | **실질 완주 신호** |
| **`option_xlsx_download`** | `options` | `RegistrationSheet.tsx` | 옵션 양식 사용률 |
| **`image_edit_open`** | `context` (`main`\|`extra`) | `DomeggookImportView.tsx` `openSlotEditor()` | 파이프라인 실제 연결 |

**`reason` 값** (`LookupFailReason`, `shared/utils/analytics.ts`): `url_parse`(사용자 입력) · `not_found`(404) · `api_error`(4xx·5xx) · `network` · `none`(성공)
**`license` 값**: `usable` · `blocked`(LicenseGate 차단) · `unknown`(조회 실패)
**`section` 값** (`SheetSection`): `category` `name` `price` `stock` `option` `detail` `info` `delivery` `return` `tag` `code` `other`

**설계 메모**
- 시트의 복사 15곳이 전부 `copyText()` 단일 함수를 지난다 → **`COPY_LABEL_TO_SECTION` 매핑 한 곳만 고치면 전 섹션이 계측된다.** ⚠️ `copyText` 호출 라벨을 바꾸면 이 표도 같이 고칠 것 (누락 시 `other`로 집계)
- 이미지 편집 모달을 여는 경로 2개(대표·추가)를 `openSlotEditor()`로 합쳐 계측 지점을 하나로 만들었다
- `DomeggookItemError`(HTTP status 보유)를 도입해 실패 사유를 정확히 분류한다 — 기존 `error.message` 처리 경로는 그대로 동작

> **`license: 'blocked'` 비율이 특히 중요하다.** `LicenseGate.tsx`가 이미지 사용 미허용 상품을 차단하는데,
> 그 비율이 높으면 **그 자체가 최대 이탈 지점**이다. 지금까지는 알 방법이 없었다.

### GA4 대시보드 설정 (배포 후 대표/운영)

`sheet_view` · `section_copy` · `image_edit_open` 3종을 GA4 **주요 이벤트**로 등록해야 탐색에서 바로 잡힌다.

### 배포 후 판정 (+7일)

1. `sheet_view` 대비 `section_copy` 비율 = **진짜 완주율**
2. `lookup_fail_reason` 분포 = 진입 단계 최대 이탈 원인
3. `image_edit_open` 발생률 = 파이프라인(차별화 축)이 실제로 작동하는지

## AI 판단 가동 절차 (구 launch/ai-verdict-setup.md 흡수 — 운영자용)

키워드 분석 페이지의 "AI 판단" (카카오 로그인 + 하루 5회 무료)을 가동하기 위한 대표 액션 3가지.
전부 완료 전까지 UI는 "준비 중" 안내로 안전하게 동작한다.

### 1. 카카오 로그인 연결 (카카오 개발자 → Supabase)

1. https://developers.kakao.com → 애플리케이션 추가 (앱 이름: 오토셀러)
2. [앱 설정 > 플랫폼] Web 플랫폼 등록: `https://www.auto-seller.co.kr` (+ 로컬 테스트용 `http://localhost:3000`)
3. [제품 설정 > 카카오 로그인] 활성화 ON
4. **Redirect URI 등록**: `https://<SUPABASE_PROJECT_REF>.supabase.co/auth/v1/callback`
   - Supabase 대시보드 > Authentication > Providers > Kakao 화면에 정확한 Callback URL이 표시됨 — 그대로 복사
5. [제품 설정 > 카카오 로그인 > 동의항목] 닉네임·이메일 동의 설정 (이메일은 선택 동의로 시작 가능)
6. [앱 설정 > 앱 키]의 **REST API 키** + [제품 설정 > 카카오 로그인 > 보안]의 **Client Secret**(발급+활성화) 확보
7. Supabase 대시보드 > Authentication > Providers > **Kakao 활성화** → REST API 키/Client Secret 입력
8. Supabase > Authentication > URL Configuration:
   - Site URL: `https://www.auto-seller.co.kr`
   - Redirect URLs에 `https://www.auto-seller.co.kr/**`, `http://localhost:3000/**` 추가

### 2. Anthropic API 키

1. https://console.anthropic.com → API Keys → 키 발급
2. `.env.local`에 추가 후 **Vercel 환경변수에도 동일 등록** (Production):

```
ANTHROPIC_API_KEY=sk-ant-...
# (선택) 모델 오버라이드 — 기본값 claude-haiku-4-5-20251001
# ANTHROPIC_VERDICT_MODEL=claude-sonnet-5
```

- `NEXT_PUBLIC_` 접두사 금지 (서버 전용 키)
- 비용 감각: Haiku 기준 판단 1회 ≈ 1원 미만 → 하루 5회 × 사용자 수로 통제됨

### 3. 사용량 테이블 생성 (Supabase SQL Editor에서 1회 실행)

> Supabase MCP 인증 후 요청하면 Claude가 `apply_migration`으로 대신 적용 가능.

```sql
-- AI 판단 일일 사용량 기록 (KST 자정 기준 카운트)
create table if not exists public.ai_verdict_usage (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null references auth.users(id) on delete cascade,
  keyword text not null,
  created_at timestamptz not null default now()
);

create index if not exists ai_verdict_usage_user_created_idx
  on public.ai_verdict_usage (user_id, created_at desc);

alter table public.ai_verdict_usage enable row level security;

-- 본인 행만 조회/기록 가능. delete/update 정책 없음 = 사용자가 쿼터를 리셋할 수 없음
create policy "select own usage" on public.ai_verdict_usage
  for select using (auth.uid() = user_id);
create policy "insert own usage" on public.ai_verdict_usage
  for insert with check (auth.uid() = user_id);
```

### 완료 확인

1. 키워드 분석 > 검색 → 최상단 AI 판단 카드에 [카카오 로그인하고 AI 판단 받기] 노출
2. 카카오 로그인 → 원래 페이지(`?keyword=` 유지)로 복귀
3. [AI 판단 받기] → 판정(추천/보류/비추천) + 근거 + 남은 횟수 표시
4. 6회째 시도 → "오늘 무료 횟수(5회)를 모두 사용했어요" 안내
